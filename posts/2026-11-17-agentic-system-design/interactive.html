Agentic System Design, Visualized

The agent design patterns published by Google, Anthropic, Microsoft, OpenAI and Cognition, drawn as one family. A chooser turns your requirements into an architecture, and the figures cover the parts that decide whether it works: context, tools, long runs, safety, protocols and evals.

01The autonomy ladder

Every agentic system sits on one rung of a ladder. Each rung up lets the model decide more, and costs more calls, more latency and more ways to fail. Climb only when the rung below cannot do the job.

02The agent loop

An agent is a model, a set of tools and instructions, run in a loop. Each turn, the model either calls a tool and reads the result, or stops. Press Play to watch one task go round the loop.

03The twelve patterns

Every published pattern, drawn the same way. Purple boxes are model calls, grey diamonds are code, teal boxes are tools, amber is a person. The badge says who picks the next step. Click a pattern for when to use it and when not to.

04One idea, four names

The vendors name the same structures differently. This map lines them up, so a pattern you read about in one guide can be found in the others.

05The multi-agent rule: parallel reads, single-threaded writes

Anthropic's research system and Cognition's coding agent seem to disagree about multi-agent design. They agree once you sort the work by whether agents read or write.

06Context is the budget

Every token in the context window competes for the model's attention, and recall degrades as the window fills. Turn the techniques on to see how a long run stays inside its budget. Token counts are illustrative.

07Long runs: memory lives in files, not in the context

A task that spans hours outlives any one context window. Anthropic's long-running harness gives each new session the state it needs through files: a feature list, a progress log and git history.

08Safety is architecture

Prompt injection cannot yet be filtered out reliably, so the safe designs are the ones where a fooled model can do little harm. Three tools decide that: the lethal trifecta, tool risk tiers, and guardrails at every edge of the loop.

09MCP for tools, A2A for other agents

Two open protocols cover the two kinds of connection an agent makes. MCP connects an agent to tools and data. A2A lets an agent hand a task to another agent it cannot see inside.

10Evals: pass@k is not pass^k

Agents are non-deterministic, so one run says little. pass@k asks whether any of k tries succeeds; pass^k asks whether all of them do. A customer-facing agent lives or dies on pass^k. Drag the per-try success rate.
